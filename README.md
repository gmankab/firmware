# Recompile firmware from auditable source

Research and development tooling for reconstructing firmware files and
checking generated bytes against pinned original references. The Xiaomi Pad 5
(`nabu`) is the first supported target.

**This repository does not currently produce a full set of independently
reconstructed, newly OEM-authenticated firmware.** Equal bytes from typed
instruction encoding do not demonstrate independent high-level semantics or
hardware boot compatibility.

## Quick start (offline, under 4 GiB RAM)

Use the pinned Rust 1.99.1 toolchain (installed locally, or supply it through
`PATH`) and run:

```bash
export CARGO_TARGET_DIR="$PWD/target-lowmem"
./tools/low-memory-build.sh check
./tools/low-memory-build.sh build
./tools/low-memory-build.sh test
./tools/low-memory-build.sh release
./tools/check-local.sh
```

The large Venus controller and tail modules compile as separate crates. The
release build deliberately uses `opt-level=0` to respect memory limits; it is
not equivalent to an optimized production firmware build.

## Firmware status and verification

```bash
python3 -m tools.firmware images
python3 -m tools.firmware coverage venus.mbn
python3 -m tools.firmware status --check
python3 -m tools.firmware verify-reference venus.mbn /private/venus.mbn
python3 -m tools.firmware compare venus.mbn /private/venus.mbn /tmp/fragment.bin --offset 0x4000
```

`reference/xiaomi-nabu/coverage.toml` is the canonical coverage ledger. It
separates reported source/layout bytes from missing or external bytes; original
firmware is never stored in this repository. The unified CLI refuses an
unsupported full-image `build`. To build the fully source-derived
`modemuw.jsn`, pass a compiled `firmware-tools` binary to the CLI's `build`
command.

## Repository navigation

- `crates/` — checked Rust instruction encoders, image formats and device
  builders. `venus-controller` and `venus-tail` are memory-isolated crates.
- `tools/` — command-line inspection, assembly, verification and local gates.
- `sources/xiaomi-nabu/` — textual firmware assembly fragments.
- `reference/xiaomi-nabu/` — pinned hashes, coverage plans and verified
  metadata, not proprietary firmware.
- `tests/` — Python regression and structural tests, runnable offline.
- `docs/` — current status, building/decompilation guides, historical
  checkpoints and audit evidence.
