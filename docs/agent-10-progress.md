## Checkpoint 02 — hash from generated segments only

- Added `ImagePlan::generated_slice(range)` that fails on the **first missing offset** or any externally imported signature/certificate byte; this prevents an accidental copy of unimplemented OEM bytes from being reported as new source-derived ELF code.
- Added `sha384_table_from_generated_plan(elf, hash_index, plan)` for generic Qualcomm ELF32/MBNv6 layouts. It uses the parsed program-header order, a zero digest for the selected hash segment and zero-file-size BSS, rejects wrong selected header and impossible PT_LOAD file/memory sizes, and refuses incomplete or externally imported hashed inputs.
- Refactored A640 `partial_container()` to obtain segment hashes via this generic checked builder **before** placing the generated digest table, rather than passing a manual array of slices.
- Independently regenerated the A640 ELF32+MBNv6 output and tested against the exact 14,256-byte original using the externally supplied original authentication field kept outside the repository. Byte differences = **0**. SHA-256 of both files = `bb1b61bae977aab5e5a68bd88848f4479c8d156911d96c7de73f7195b674db06`.
- `tools/verify-mbn-signatures.py`/OpenSSL verified 2 ELF SHA-384 digests, the embedded three-certificate chain, and the RSA-PSS signature against that embedded chain. Embedded root fingerprint = `c924a35f39ce1cdd1b8d5a9f3b8e3c51317930431d7a9dd5a55028cf6965fe65`. This is **embedded-chain consistency, not a hardware-trusted Qualcomm signing root**.
- Signing/certificate material stays outside Git and is never linked as an output artifact. There is no independently generated valid OEM signature.

## Checkpoint 03 — six-ELF coverage and authentication audit

- Added `elf_file_coverage::{checked_elf_header_plan, compare_known_first_page}` and the `firmware-tools audit-elf-coverage NAME ORIGINAL` command. It verifies source-generated ELF first-page bytes, counts unique program-header file-backed bytes, reports file-only executable ranges, memory-only/BSS accounting, authentication extent and the **first unknown file range**. No segment payload is silently copied from the reference.
- Fixed false corruption findings for legitimate **zero-file-size BSS PT_LOAD** entries whose `p_offset` exceeds physical EOF (present in ADSP/CDSP/modem). Such entries contribute memory-only bytes, **zero** file bytes.
- Audited all six exact reference revisions by SHA-256 from `reference/xiaomi-nabu/firmware.sha256`. Physical MBN lengths: A640 `14,256`, ADSP `14,430,684`, CDSP `9,455,252`, modem `5,101,612`, Venus `1,159,200`, WLAN `4,331,136` bytes. The new generic header-only plans cover **4,096** independently generated bytes per image; all other bytes remain explicitly unknown to that report. For A640, the separate specialized container generator covers **7,856** bytes, not merely 4,096.
- Ran the existing external OpenSSL/RSA-PSS verifier against **all six unmodified reference MBNs**. All six pass their embedded SHA-384 segment hashes (2/13/8/20/4/6 segments respectively), internal three-certificate chains and OEM RSA-PSS signature verification against embedded roots. They share the embedded-root SHA-256 `c924a35f39ce1cdd1b8d5a9f3b8e3c51317930431d7a9dd5a55028cf6965fe65`.
- **Limit:** This is internal certificate-chain/signature consistency, not proof of Qualcomm or Nabu hardware trust. No new signature was generated, and the remaining ADSP/CDSP/modem/Venus/WLAN executable programs have **not** been independently rebuilt by Agent 10.

## Checkpoint 04 — reference-bound, full-byte A640 proof

- Added `a640_container::audit_complete_reference(reference)` and `firmware-tools verify-a640-complete ORIGINAL_MBN`. It verifies the target input is exactly 14,256 bytes, checks each independently generated region before examining OEM bytes, borrows exactly `0x1138..0x2a38` of original authentication, creates a comparison in memory, compares all bytes, and reports source-generated/external counts separately. It never writes original OEM signing material to the repository.
- The original A640 result: **14,256 / 14,256** identical bytes; independently generated `7,856`, externally borrowed `6,400`, missing `0` in the *comparison*. The partial source-only plan still has a 6,400-byte authentication hole and cannot be emitted as a standalone signed image.
- Added the exact A640 reconstruction audit to `tools/verify-xiaomi-nabu.sh`, alongside the pre-existing executable comparison, six hash checks and optional OpenSSL verification.
- Synthetic reference tests cover correct dimensions, missing/truncated reference and a changed independently generated code byte. Byte identity against borrowed authentication is not proof of a new signature. Verify the reference's RSA-PSS signature separately with OpenSSL and an explicitly pinned root if such trust is needed.

## Checkpoint 05 — six structured Qualcomm signed-policy profiles

- Added `qcom_mbn_profiles::KNOWN_MBN_POLICIES`, `unsigned_header_and_policy()` and `unsigned_metadata_plan()` for the six known Xiaomi Nabu ELF32/MBNv6 images. This reconstructs the 12-word MBNv6 **unsigned header** and 30-word SoC/software policy, using semantic fields and checked segment/hash sizes, not raw original header dumps.
- All six compare byte-for-byte against their original image on the **4,096-byte ELF first page + 48-byte MBNv6 header + 120-byte OEM policy = 4,264 generated bytes per image**; the first unknown byte is at `0x10a8` (start of the still-unreconstructed SHA-384 hash table).
- Added `firmware-tools audit-mbn-unsigned NAME ORIGINAL` to report generated bytes, exact file size and first incomplete span. The command refuses unknown profiles or wrong revision bytes.
- Refactored A640 signed-container generation to reuse the shared profile table, removing duplicate policy constants. Its independent 7,856-byte output and the complete 14,256-byte borrowed-authentication comparison remain byte-identical to the original.
- Profile values are public image/SoC policy data (`image_id`, `software_id`, `hardware_id`, `oem_id`, supported SoC, rollback policy and original pointer *fields*). They are not signing credentials or proof of hardware trust. The other five MBN hash tables are **not** generated from proprietary executable reference data.
