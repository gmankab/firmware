## Delivered implementation

### Strict source joining and accounting

`crates/firmware-tools/src/mbn_source_slices.rs` provides `MbnSourceSlices`,
`SourceSlice`, `SourceKind`, and canonical `SourceCoverage` reports.
It accepts individually named, independently generated fragments anchored to
an exact program header and file offset. A batch is transactional: a bad later
fragment cannot leave an earlier fragment inserted. Duplicates, overlaps,
empty names or ranges, offset overflow, crossing segment bounds, and attempts
to import the hash/authentication segment are rejected.

Code, data, metadata, explicit layout fill, external authentication and unknown
bytes are separate categories. `PF_X`/`PF_W` permissions are a second inventory;
they do not establish source provenance or instruction counts. Overlapping
load views are counted by a disjoint file-byte union. NOTE/DYNAMIC aliases
cannot inflate that union. Memory-only PT_LOAD tails, including BSS offsets
beyond EOF, never become file bytes.

Explicit alignment and segment padding APIs retain a named source rule. Hash
generation requires complete hashed source plus all other non-authentication
file bytes. Missing source/layout fails closed; original external authentication
can be added only after source finalization and remains external. The immutable
plan accessor cannot bypass these checks. The constructor also rejects payload
descriptors overlapping the first-page zero-alignment policy: without this
check, a changed layout could silently classify missing payload as zeros.

The constructor deliberately uses the six existing Nabu unsigned-policy
profiles. Arbitrary device policies and dual QTI/OEM signer profiles remain
unsupported and fail closed. Caller-supplied provenance is a claim requiring
source review and comparison; no API can determine whether a caller copied OEM
payload bytes.

QRISC metadata word and terminal shader padding, adds explicit 4 KiB layout
alignment, and derives SHA-384 entries from generated bytes only.

unchanged. Byte identity is not complete behavioral validation.

### Original-reference signature checks

`tools/verify-mbn-signatures.py` now checks that the hashed header span binds
the full ELF program-header table, rejects invalid PT_LOAD sizes and hash/auth
overlap, requires exact authentication-segment consumption, and rejects
nonminimal DER lengths and duplicate certificates. OpenSSL validates each
declared adjacent certificate pair, the complete chain, and the embedded
root's self-signature using the explicit embedded trust input. RSA-PSS MGF1
uses SHA-256 explicitly; salt length remains automatically detected.

An explicit `--verification-time UNIX_EPOCH` makes certificate validity
reproducible. The checkpoint uses the tested implementation commit's epoch
`1792943309`. All six pinned originals pass their existing signatures and
three-certificate chains, totaling 53 verified non-placeholder segment hashes.
The pinned embedded-root DER SHA-256 is
`c924a35f39ce1cdd1b8d5a9f3b8e3c51317930431d7a9dd5a55028cf6965fe65`.
These checks establish consistency with that original root, not Qualcomm or
device hardware trust. No new signature, certificate or private key is created.

### Reproducible build manifest

`tools/mbn-reproducibility.py` archives the exact committed Git tree into two
fresh source directories, creates isolated Cargo homes/targets, builds offline
and locked, fixes SOURCE_DATE_EPOCH, remaps source paths and clears inherited
Cargo/compiler overrides. A standalone Rust probe links each freshly built
library; central CLI changes are unnecessary.

Each build exports only generated source regions with exact offsets and
hashes. Python independently cross-checks the Rust geometry and provenance.
With references supplied, every exported region from **both builds** is
compared to the same interval of the pinned original, in addition to the
legacy audit. This direct comparison prevents a deterministic but wrong strict
export from passing merely because the separate legacy generator is correct.
The original six signatures are then checked, and both A640 full comparisons
use only the original external authentication field.

The output is canonical JSON with source commit/tree, tool versions, commands,
region hashes, holes, categories, ELF permissions/BSS, reference checks and
explicit trust limits. Output publication is atomic and refuses overwrites,
including a competing creator. Reference firmware/authentication and rebuilt
full images remain temporary and are not published by this harness.

Both source outputs and both host tools were byte-identical in this run.
The source-output fingerprint is
`fb255724cfc44fe43e892f31bc0e5a22504176bb7324a5981318b9ab0ee73714`.
The compiler/linker/system installation is not packaged and hash-pinned, so
the report explicitly does not claim a fully hermetic toolchain.
