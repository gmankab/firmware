# Agent 19 — Pinned postmarketOS Novatek DLM seed hashes

The Agent 19 sparse DLM assembler has two distinct inputs: **9,353 uniquely source-authored DLM bytes** and **27,093 opaque, externally supplied bytes**. The latter cover **61 non-overlapping file ranges**; transforms produce another 13,106 **reference-dependent bytes**. The full DLM spans `[0x22000,0x2e190)` and contains 49,552 bytes. The 13,106 dependent bytes must not be claimed as independent recovered source.

## SHA-256 manifest

The source-only file `crates/firmware-tools/src/devices/xiaomi_nabu/novatek/dlm/novatek_dlm_seed_hashes.tsv` records inclusive start, exclusive end and SHA-256 for each of the **61 ranges in the pinned postmarketOS revision**. It includes no firmware/seed bytes. Whole reference image SHA-256: `8b845514621ebfd95759a0919f3aa3d825314abb478a7cad1c3fb4c6872b70b5`. This is an **integrity pin**, not an OEM authentication key or certificate; tiny seed ranges still contain proprietary data not generated by source.

The Rust module `novatek_dlm_seed_manifest.rs` validates manifest schema, profile, full-image reference identifier, lengths, sorted ranges and digests against the live sparse plan, then validates **every supplied external seed before the CLI assembles/writes output**. The generic `novatek_dlm_sparse::assemble` continues to accept arbitrary synthetic seed inputs for unit tests, but the user-facing `assemble-sparse` path is now pinned by default. There is no `--ignore-sha` option.

The independent Python checker uses standard-library `hashlib` (not the Rust hashing engine) and verifies the same profile, plan and 61 digests. Source changes to the DLM map require deliberate manifest revision and code review; changing the source/authorship ledger silently is rejected.

## Reproduction (private inputs outside Git)

```sh
cargo run --offline --locked --bin novatek-dlm -- sparse-plan > /tmp/dlm-sparse-plan.json
cargo run --offline --locked --bin novatek-dlm -- seed-manifest > /tmp/dlm-seed-manifest.tsv
cargo run --offline --locked --bin novatek-dlm -- verify-seed-manifest /private/postmarketos-novatek_nt36523_fw.bin
python3 tools/verify-novatek-dlm-seed-manifest.py \
  --manifest /tmp/dlm-seed-manifest.tsv --plan /tmp/dlm-sparse-plan.json \
  --reference /private/postmarketos-novatek_nt36523_fw.bin

# External seed directory holds exact private ranges named:
# dlm-external-<start-hex6>-<end-hex6>.bin
# It MUST NOT be added to Git or uploaded as a checkpoint artifact.
cargo run --release --offline --locked --bin novatek-dlm -- \
  assemble-sparse /private/external-seeds /tmp/rebuilt-DLM.bin
python3 tools/verify-novatek-dlm-seed-manifest.py \
  --manifest /tmp/dlm-seed-manifest.tsv --plan /tmp/dlm-sparse-plan.json \
  --seed-dir /private/external-seeds
```

A wrong-revision or changed seed fails **with a specific file range and SHA-256 mismatch** before output creation. Missing, extra, reordered, truncated and boundary-shifted seed inputs fail. A directly tested altered first seed was rejected and produced no output file. The full pinned reference conditional DLM rebuild matches byte for byte, and all 12 independent CRC-32/MPEG-2 fields and the derived mirror remain governed by the existing envelope checks. The final output is DLM-only; it is neither a complete flashable image nor newly OEM-signed.
