# Agent 20-19 — narrow descriptor-bank relocation (checkpoint 19)

**Status:** a verified **reference-dependent** data-generation relationship,
not independent firmware source recovery or newly decoded NDS32 executable.

The *postmarketOS* Novatek reference is pinned by SHA-256
`8b845514621ebfd95759a0919f3aa3d825314abb478a7cad1c3fb4c6872b70b5`.
Its two DLM banks contain one four-entry directory and an adjacent narrow
controller-input record window. The upper bank is file `+0x4000` from the
lower; original lower-bank values remain entirely external/unrecovered.

| Lower file interval | Derived upper file interval | Bytes | Rule |
| --- | --- | ---: | --- |
| `[0x25220,0x25230)` | `[0x29220,0x29230)` | 16 | Four 32-bit descriptor indices: add `0x1000` to the low 15-bit word index; preserve unknown high selector/config bits |
| `[0x25460,0x2574c)` | `[0x29460,0x2974c)` | 748 | Copy an input buffer/controller window and add `0x10` to two little-endian halfword indices in each of 18 40-byte records **except records 8 and 9** |
| **Total** | | **764** | Exact, externally dependent output; **zero** new source-authored bytes |

The four directory entries have low-15-bit values `0xc8c`, `0xcaf`, `0xcd2`,
`0xcf5`: scaling by four and adding DLM file base `0x22000` reaches four
140-byte descriptor starts at `0x25230 + i*0x8c`. The upper bank offsets
are `+0x1000` in index units, but the upper bits still have unknown meaning.
This geometry corroborates identifying the words as indexed descriptor
references. The values themselves remain classified as externally supplied.

The input record window begins with 64 unchanged bytes. The 18 record heads
start at `0x254a0` with a 40-byte stride. Exactly **16** heads relocate
both little-endian 16-bit values by `0x10` and the two special heads at
indices **8 and 9** are unchanged. The 18th head is the final four bytes of
the interval; subsequent record bytes are already covered by checkpoint-12's
separate `input-ring-metadata` bank-copy alias starting at `0x2574c`. The
newly derived destination intervals end *before* any previously authored or
dependent output, preventing overlap and double counting.

The Rust and independent Python encoders perform checked arithmetic and
reject wrong intervals, truncated inputs, index overflow and modified
secondary bytes. They do not serialize OEM payload bytes into the source
repository; all 764 generated bytes depend on the supplied lower bank.
