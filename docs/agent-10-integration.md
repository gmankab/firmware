# Agent 10 — integration of checked ELF/MBNv6 and A640 tooling

## Baseline and scope

**Requested shared starting point:** checkpoint 50, `b7ed4b5…` from
`checkpoint-50-venus-33872.bundle`. **Not available in this agent session.**
The only mountable base was `recompile-firmware.bundle` at commit
`69ebf0d1c50859189a9196a21155c388ac914d7b`.
The Agent 10 branch therefore descends from **that older base**, not
checkpoint 50. This fact must remain explicit throughout integration.

Agent 10 implemented shared `ImagePlan` provenance, source-only SHA-384 table
construction, strict MBN file-layout auditing, signed ELF policy reconstruction
for the six known Qualcomm MBNv6 images, A640 source/externally-authenticated
assembly, pinned A640 exact-output checking, SHA-384/ELF anti-overlap checks,
machine-readable byte-coverage manifests, and a revision-pinned six-image audit.

DSP program implementations. Nothing in this branch is a new OEM signature.

## Merge into the real checkpoint-50 branch

The Agent 10 full bundle is sufficient to fetch the complete branch history.
A `git format-patch` mbox of all Agent 10 commits is also supplied separately;
that mbox is generally easier when another agent changed shared `main.rs`,
`mod.rs`, `lib.rs` or `ImagePlan` since the common ancestor.

```sh
# From the *actual* checkpoint-50 repository, not this agent's old base:
test "$(git rev-parse --short HEAD)" = b7ed4b5
# Preserve author and committer attribution when applying patches.
export GIT_COMMITTER_NAME=Codex GIT_COMMITTER_EMAIL=codex@openai.com
# Use the supplied mbox containing all commits from 69ebf0d..AGENT10_HEAD.
git am --3way /path/to/agent-10-for-checkpoint50.mbox
# On a conflict: inspect and resolve shared-interface wiring manually,
# then `git add ... && git am --continue`; run tests before merging others.
```

There is **no claim** that this mbox cleanly applies to checkpoint 50:
that exact repository was absent and the patch is only independently replayed
against the mountable older base. Do not overwrite another agent's Venus
fragments or delegate their ELF executable reconstruction to the generic
MBNv6 build code. Keep all source-generated executable ranges explicitly
accounted for in the shared `ImagePlan`; no source file may silently import OEM
reference code, certificate bytes or pad absent firmware bytes.

## Verification after integration

```sh
cargo test --workspace --offline --locked
cargo build --workspace --release --offline --locked
python3 -m unittest discover -s tests -p 'test_*.py'
git diff --check
# Private source directory containing exact six revisions; no files go to Git:
python3 tools/audit-nabu-mbn-sources.py /private/NABU_QCOM_MBN_DIR \
  --firmware-tools target/release/firmware-tools \
  --verify-embedded-signatures > /private/six-mbn-coverage.jsonl
# Independently generated A640 code + original OEM signature/cert field:
firmware-tools verify-a640-complete /private/NABU_QCOM_MBN_DIR/a640_zap.mbn
```

All six original MBNv6 images pass structural metadata comparisons and SHA-384
digest agreement. Their *original* embedded X.509 chains and OEM RSA-PSS
signatures verify against the pinned embedded root fingerprint. This **does
not** verify Qualcomm hardware trust nor create OEM signing credentials.

## What remains unimplemented

- A640 has 7,856 source-generated bytes and requires the original 6,400-byte
  OEM authentication field for full byte-identical reproduction. An entirely
  *new* trusted OEM signature cannot be created without the authorized signer.
- ADSP, CDSP, modem, Venus and WLAN have 4,264 source-generated ELF/header/
  signed-policy bytes each in this Agent 10 baseline. Their remaining code,
  data, signed hash tables and original signature/certificate fields must be
  generated independently or remain clearly external and non-source-generated.
- Agents 1–9 are responsible for their respective firmware executable payloads.
  Their incoming fragments must be integrated, cross-checked and hashed before
  the generic `MbnSourceBuilder::generate_hashes` can produce full source-based
  signed-image inputs.
- Re-verification on checkpoint 50 and on the multi-agent merged branch is
  **required** before claiming integrated or complete firmware artifacts.
