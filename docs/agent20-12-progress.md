**Disjoint source-generated code** within Agent 12's exclusive ranges:

| File interval | ELF vaddr | Physical address | Bytes | Content |
|---|---|---|---:|---|
| `[0x7c000,0x7c028)` | `0xc0890000` | `0x8e090000` | 40 | Hexagon locked-memory conditional exchange/retry helper |
| `[0x7c028,0x7c030)` | `0xc0890028` | `0x8e090028` | 8 | Explicit Hexagon `brkpt` trap guard, generated instructions (not unknown fill) |

| `[0x446088,0x4460d8)` | `0x1e400088` | `0x90000088` | 80 | Checked byte/word zeroing helper with loop packet layout |

**Total independently generated: 280 bytes**, of which **272 callable
instructions** and **8 explicit architectural trap instructions**. There are
**zero differences** against the pinned original. Neither region claims to
cover the intervening firmware nor later code. In particular, firmware byte
`0x4460d8` and onward is **not** output as source-generated executable;
several following words are resource strings and linker metadata, not code.

`modem_late_atomic.s` models the atomic conditional-store algorithm with
explicit packet and branch labels. LLVM6 schedules a two-word conditional
ADD and comparison/branch packet in reverse order. The checked
`restore_atomic_packet_order` procedure validates instruction classes and
packet marker state then restores the source's original legal order; it
never replaces bytes from the proprietary reference. The auxiliary startup
uses checked Hexagon C2_tfrrcr architecture fields for the unsupported
`framelimit = r0` control-register alias; all other operations use LLVM6 MC.

Deterministic generation and strict reference verification:

```sh
python3 tools/assemble-modem-late.py \
  --llvm-mc /path/to/llvm6/bin/llvm-mc \
  --reference /private/modem.mbn \
  --output-dir /tmp/agent12-modem-late
```

The tool rejects an incorrect modem SHA-256, incorrect Hexagon ELF machine,
unexpected executable segment virtual/physical addresses or sizes,
invalid source-generated packet layout, and every byte mismatch. Program
headers confirm `[0x7c000,0x1ffcf0)` vaddr `0xc0890000` and
`[0x446000,0x457da4)` vaddr `0x1e400000` are executable; these reservations
stay exclusive to Agent 12.

**Known limitations:** no full modem, no reconstructed OEM signature, no
flashable image or verified hardware execution. This is an original,
human-readable Hexagon V60 assembly reconstruction of selected functions,
not a wholesale reconstruction of the 1.6 MiB first later executable segment
or a high-level C implementation. The remaining function ranges must still
be identified and source-reconstructed independently.

## Checkpoint 02: controller callback and cleanup path

Reconstructed an additional **96 executable bytes** at modem file
`[0x7c040,0x7c0a0)`, ELF virtual `[0xc0890040,0xc08900a0)` and physical
`[0x8e090040,0x8e0900a0)`. The routine performs a controller logging call,
checks an absolute controller word, looks up callback metadata and conditionally
calls a cleanup handler. The executable Hexagon region `[0x7c000,0x7c0a0)`
now has **160 contiguous generated bytes**, including 8 bytes of deliberate
Hexagon breakpoint instructions (not implicit fill). Together with the
216-byte auxiliary executable fragment, total **376 independently generated
bytes** match the exact pinned modem revision.

LLVM6 schedules two compound comparison/branch + extender packets in a
byte-different legal order and ends one adjacent constant-move packet
prematurely. The checked `restore_controller_packet_order` procedure verifies
the Hexagon opcode classes and parse markers, reorders the three-word
operation packets, and joins one architectural duplex as the reference does.
This matches original packet semantics without importing OEM instruction bytes.
The generic source remains unmodified; this checkpoint only adds new Agent 12
files and changes Agent 12 tests/docs/tooling.

## Checkpoint 03: auxiliary constructor walker and guarded handoff

Added **108 byte-identical Hexagon V60 executable bytes** in two additional
nonadjacent source routines within the second `PT_LOAD`:

- File `[0x446200,0x446254)` = **84 bytes** of initialization code. The
  function sets up an 8-byte frame, probes a configured runtime pointer,
  initializes control globals, then walks a descending constructor table
  until it encounters a zero terminator. This is generated by named
  `.h`/`.l` register assignments and a symbolic backward loop branch.
- File `[0x446260,0x446278)` = **24 bytes** of conditional callback/handoff
  code, with a symbolic PC-relative jump to offset `0x9cc0` within its
  executable load. The original intervening `[0x446254,0x446260)` is
  NOT treated as independent code or fabricated alignment bytes.

The LLVM6 scheduler marked the first scalar zero-register write as a packet
end, while the reference architecture groups it with an adjacent valid
Hexagon duplex. The checked `restore_aux_init_packet` routine validates the
scalar opcode class, duplex class and expected parse markers before changing
*only* that parse field to continue. No reference OEM word is written.

**Total source-generated later modem byte coverage:** **484 bytes** in four
intervals, comprising **476 executable operation bytes and 8 explicitly
encoded `brkpt` guard bytes**. Every included byte matches the pinned
`modem.mbn` with the exact SHA above. The main later modem executable
`[0x7c0a0,0x1ffcf0)` and other large regions remain unimplemented; outside
Agent 12 ownership, early modem `[0x3000,0x4058)` remains Agent 06's work.
