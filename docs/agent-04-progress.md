## Verified input and architecture

- Input: `usr/lib/firmware/qcom/sm8150/Xiaomi/nabu/adsp.mbn` from recovered,
  intact `firmware-xiaomi-nabu-1-r2.apk`. Source package is private input, not
  tracked by Git.
- Exact reference SHA-256:
  `4b579e5dc1333d634e5bdc93f3314e357e0e30dab7140833f6cc7aef086b1c1e`.
- ELF32 little-endian, `e_machine = 164` (Qualcomm DSP6/Hexagon),
  `e_flags = 0x66` (v66), ELF entry/physical entry = `0x8be00000`.
- First `R E` PT_LOAD: file `[0x3000, 0x521c)`, `p_filesz = 0x221c`,
  `p_memsz = 0x3000`, ELF vaddr = `0xf0000000`, physical addr =
  `0x8be00000`. File offset is **not equal** to CPU vaddr/paddr.
- The entry fragment `[0x3000, 0x3024)` comprises precisely nine A32-sized
  *Hexagon* (not ARM32) packets/instructions: initial jump, six vector
  self-loop traps, distant jump to RX-relative `0x1158`, and initial `r0=0`.
  Generated from `tools/adsp-boot-vectors.S`, no binary `.word`/`.incbin`.
  Checkpoint 08 adds the adjacent `[0x3024,0x3044)` (32-byte) V66
system-control tail to form a **68-byte contiguous boot prefix**
`[0x3000,0x3044)`. This uses narrow typed Hexagon encoders for `SSR`,
`SYSCFG`, `setbit`, `dckill`, `ickill`, and a forward jump. LLVM6
independently assembles the supported `setbit`/`jump` operations; the
other V66-only encodings are field-generated and cross-checked against
the separate Rizin decoder and two independent system-register usages
within the original image. This is not a complete V66 toolchain.
The first 36 independently generated bytes have SHA-256:
  `e945606214436af167625a339bfa36f4df34c5860f1507649d29b755d608550b`.
- The generator compiles source with LLVM6 Hexagon `-mcpu=hexagonv65` **only
  for instructions proven common to v65/v66**. It refuses relocations and
  invalid ELF section layouts. For other executable v66 instructions,
  do not assume the v65 assembler is a complete or correct toolchain.

## Checkpoint 02: independent timer and controller fragment

A second, **disjoint** fragment has now been independently source-assembled
at file offsets `[0x41e0,0x4980)` (`0x7a0 = 1,952 bytes`), executable PT_LOAD
relative `[0x11e0,0x16a0)`, physical addresses
`[0x8be011e0,0x8be016a0)`. The initial 112 bytes formed checkpoint 02;
checkpoint 03 adds the adjacent 512 bytes of actual hardware-register
initialization (three paths, each with nine named configuration writes). Checkpoint 04
adds another 248 adjacent bytes that configure the MMIO controller, mask
interrupt bits, invalidate D-cache entries, and invoke the polling helper.
Checkpoint 05 adds 224 more bytes of controller MMIO mask updates, IRQ
class flags, status polling, and exception-vector reset. Checkpoint 06
adds 64 bytes clearing remaining exception slots and implementing two
small initialization helper returns, stopping before v66-only SYSCFG code.
Checkpoint 07 extends backward by 56 source-authored bytes from file
`0x41e0`: it programs three exception-vector MMIO slots, enforces a
memory barrier, and branches to the now-reconstructed controller code. This covers a three-instruction register-save
packet, global-timer polling/conditional retry, restoration and a return,
followed by controller status comparison against `0x100`/`0x200` and
three conditional branch destinations. The code uses source labels, combined
predicate/branch packet syntax, `immext` generated from constants and no
binary code words. Checkpoint 09 extends the second region **forward** through the 84-byte
`[0x46a0,0x46f4)` SYS_CFG register/cache handoff and two small helper
returns. It uses six narrow typed V66 system-register/cache encodings
and 13 GNU-style source expressions independently assembled with LLVM6;
one expression is a 12-byte instruction-extender/dual-op packet. The packet
boundaries are explicit, no reference bytes are used to generate code.
The resulting contiguous **1,300-byte** controller region SHA-256 is
`1a025e82bd4f0a5c6fec1f651eaac34cca931d001673af335d44ddba661e4b3e`.
The individual 84-byte handoff SHA-256 is
`e002b818f7f283a1249cbb7eccc9e673a4de59b1930f5518b8ddd9706cbc7682`.
Checkpoint 10 adds a third, contiguous **148-byte** extension
`[0x46f4,0x4788)` of three TLB helper routines. Most packets, including
predicate-controlled retries, instruction extenders, register-bit extraction
and insertion, are built by LLVM6 from original source labels in
`adsp-tlb-map.S`. Three single-word privileged TLB writes
(`tlbw(R3:2,R0)`) cannot be parsed by LLVM6; the assembler source reserves
`nop` *only during compilation*. The emitter checks all three sentinel
locations and replaces each with the narrowly checked fixed-operand V66
instruction encoder, before output. The TLB opcode is confirmed by
the independent Rizin decoder and repeated across at least five call sites.
**This is a typed architectural operation, not a copied OEM instruction
array or full TLB instruction encoder.** No unresolved sentinels survive.
The entire 148-byte extension and 1,448-byte combined controller span
match the exact ADSP reference byte for byte. SHA256 of the full controller:
`52ef02c0423ce535a9936fe9bc5cd3a22b4c355afe8b425d6c3e6fbe9c740b93`.
Checkpoint 11 extends that region by another **144 contiguous bytes**
`[0x4788,0x4818)`, reconstructing fixed-index TLB clearing, a 127-entry
clearing loop, one entry restoration, and restoration of two TLB tables.
LLVM6 assembles the packetized loops and branch offsets from source labels
in `adsp-tlb-flush.S`; five `nop` sentinels are replaced with the identical
fixed-operand `tlbw(R3:2,R0)` typed encoding. The converter rejects
unexpected sentinel locations and unresolved NOPs. The entire extension
matches the SHA-256 reference exactly. Whole controller SHA-256:
`6ca6a20b8be04e75c6cc41896019bf3d46eab35e648b4d9ad39f0fbd0453f9ea`.
Checkpoint 12 separately reconstructs the 64-byte source-authored
Hexagon hardware-loop memory-copy routine `[0x4890,0x48d0)`.
`tools/adsp-dsp-memory-copy.S` builds `loop0`/`:endloop0` packets and
post-incrementing 64-bit transfers with LLVM6, SHA-256
`b16b41de41c20fbcce631e29bb6e062a6c5bfbb4a642fe2dc603468944fef5fd`.

Checkpoint 13 closes the formerly missing `[0x4818,0x4890)` 120-byte
cache-line copy routine with fully source-assembled nested hardware loops
(`loop1` and `loop0`, `:endloop0:endloop1` packet), cache zero/fetch
operations, and three explicit architecture NOPs for alignment. LLVM6
assembles **every byte** without typed V66 substitutions. This joins the
controller region to the existing 64-byte memory-copy function, creating
one **1,776-byte contiguous independently reconstructed region** at
`[0x41e0,0x48d0)`, SHA-256
`67f5987a649b3337f4d554550745ce8c8653c175411c191c80c7e4958a510c72`.
Checkpoint 14 adds a **176-byte** reconciliation loop
`[0x48d0,0x4980)` to the same contiguous controller region. The original
source-level routine reads back TLB entries, checks page mapping boundaries,
clears protected entries under `tlblock`/`tlbunlock`, writes updated TLB pairs
and restores another source table. LLVM6 independently assembles its
branch predicates, integer operations, extenders and the hardware loop.
Seven privileged `tlbr`, `tlbw`, `tlblock` and `tlbunlock` slots have narrow
fixed-operand encoders checked against Rizin and the reference; a separate,
legitimate hardware-loop NOP at offset `0x4938` is preserved as real code.
Source: `adsp-tlb-reconcile.S`; SHA-256 of the new 176-byte fragment:
`32429769da322a73fa4b369a525c3774b3b4fabc67ee3a9ba161df884307211d`.
The joined controller is now **1,952 bytes** `[0x41e0,0x4980)`, SHA-256
`11cba27929eea73351c3e248274e8a3a0cd15e164637ce0adbc00788fb50b5fd`.
The next unreconstructed controller byte is at file offset `0x4980`.

**Cumulative independently rebuilt executable bytes: 2,020** (`68 + 1,952`).
The two rebuilt regions remain disjoint because of the large gap after the entry prefix.
The first missing executable byte is now file `0x3044`; the uncovered
interval `[0x3044,0x41e0)` must not be hidden or counted as rebuilt.

## Checkpoint 15: post-TLB bootstrap call chain

The controller image has grown by **44 contiguous source-authored bytes** at
file `[0x4980,0x49ac)`, physical `[0x8be01980,0x8be019ac)`:

- Save and restore the return link (`r17`/`lr`).
- Initialize the bootstrap stack pointer with the extended v66-compatible
  immediate `0xf0023448`.
- Call the independently reconstructed TLB reconciliation routine at
  file `0x48d0`, using an explicitly extended branch offset.
- Load controller initialization state through a GP-relative extended
  32-bit address, then call the adjacent routine beginning at `0x49ac`.
- Restore `lr` and return without importing OEM instruction words.

`tools/adsp-controller-bootstrap.S` assembles with LLVM6 Hexagon v65, which
is safe for the supported instructions used in this fragment. A forced
`immext` is required for the GP-relative address; omitting it silently
shortens the binary and changes the logical address. All 44 bytes match the
exact reference. The `counter-controller` generator now emits the contiguous
**1,996-byte** span `[0x41e0,0x49ac)` and still byte-matches the source
firmware. Including the separate `[0x3000,0x3044)` boot prefix, cumulative
independently rebuilt executable coverage is **2,064 bytes** (68+1,996).

## Checkpoint 16: guarded Hexagon cache-line duplication

Independently built **92 bytes** at file `[0x49ac,0x4a08)`, physical
`[0x8be019ac,0x8be01a08)`, from the meaningful source in
`tools/adsp-controller-cache-copy.S`. The source loads the pointer pair and
size from GP-relative controller words, skips missing/short input, then uses
Hexagon `loop0` to process 32 bytes of cache-aligned data per iteration with
`dczeroa`, paired 64-bit loads and post-incrementing stores.

The source intentionally expresses the `cmp.gt(r2,#32)` as a *non-extended*
operand and the two `add(...,#8)` operands with their smallest legal
encodings. A forced `##32` would introduce an unnecessary `immext`, and
forced extended adds produce invalid packet size. The assembler independently
chooses packet parse bits and branch displacements. No reference opcodes,
`.incbin` or `.word` instructions are present.

All **92 source-assembled bytes match the exact Nabu reference** with the
validated image SHA-256. The combined controller interval is now
`[0x41e0,0x4a08)`, **2,088 contiguous bytes**; together with the separate
68-byte boot prefix, cumulative independently reconstructed executable code
is **2,156 bytes**. The first still-missing boot byte is `0x3044`; the next
missing controller byte is `0x4a08`. All 52 Python regression tests pass.
