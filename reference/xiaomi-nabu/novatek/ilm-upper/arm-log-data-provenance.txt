Typed content and layout
------------------------
Field       Count (f64)   File interval          Meaning
ln2hi         1          [0x19bf0,0x19bf8)       High part of ln(2)
ln2lo         1          [0x19bf8,0x19c00)       Low part of ln(2)
poly          5          [0x19c00,0x19c28)       Residual log polynomial
poly1        11          [0x19c28,0x19c80)       Near-one polynomial
tab         256         [0x19c80,0x1a480)       128 reciprocal/log(c) pairs
tab2        256         [0x1a480,0x1ac80)       128 high/low center pairs
Total       530          [0x19bf0,0x1ac80)       4,240 bytes

For x = 2^k z, the algorithm uses log(x) = k*ln(2) + log(c) + log(z/c).
The reciprocal/logarithm table selects a reduction center c for z. The split
center table supports r=(z-chi-clo)*invc without a fast fused multiply-add.
The near-one polynomial handles the interval for which cancellation requires
the alternate approximation. These meanings are documented in the public C
source; no numerical values were transcribed from the OEM byte stream.

Implementation
--------------
crates/firmware-tools/src/devices/xiaomi_nabu/novatek/ilm/novatek_upper_log_data.rs

All constants are typed f64 decimal literals, each accompanied by the original
hexadecimal float from the public C source. Python float.fromhex plus shortest
round-tripping decimal serialization was used to transcribe the literals.
Every Rust scalar was then independently emitted and compared with the selected
public C constants as IEEE-754 binary64 little-endian values. Rust emits fields
explicitly, so native struct padding and host endianness are irrelevant.

Public API: emit() -> Vec<u8>, SOURCE_START=0x19bf0, SOURCE_END=0x1ac80.
The emitter accepts no firmware, source-image slice, or other external input.
